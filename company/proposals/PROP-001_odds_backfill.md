# PROP-001 ◎の単勝オッズ欠損31件の補完と、今後の記録漏れ防止

| 項目 | 内容 |

| 状態 | 会長決裁待ち |
| 起案日 | 2026-11-02 |
| 起案 | 社長（担当: データ分析部・指数開発部） |

## 1. 何をしたいか（一言で）

成績ログの「◎の単勝オッズ」が空になっている31レースを埋めて、回収率を正しく計算できるようにする。あわせて、今後は外れたレースのオッズも記録されるようにする。

## 2. なぜ（根拠の数字）

`python3 tools/sx_kpi.py` の結果（2026-05-16、36レース）:

- ◎の単勝オッズが入っているのは **◎が勝った5レースだけ**。外れた31レースはすべて空。
- このまま計算すると回収率は 208% と出るが、これは「当たったレースだけで計算した」数字で意味がない。今は回収率を出せない状態。
- ついでに、勝ち馬の名前も30件が「不明」（うち1件は◎が勝ったレース）。

欠損しているレース:

| 場所 | レース |
| --- | --- |
| 東京 | 1〜12R（全12レース） |
| 新潟 | 1, 3, 4, 5, 6, 7, 10, 11, 12R（9レース） |
| 京都 | 1, 2, 3, 4, 5, 7, 8, 9, 10, 11R（10レース） |

ログには◎の馬番（`ai_top1_no`）は全レース入っているので、その馬番の確定単勝オッズさえ分かれば埋められる。

## 3. 具体的な変更内容（3つの案）

### 案A（推奨）TARGETの成績データから埋める

1. TARGETで 2026-05-16 の成績を **CSVに書き出す**（いつもの成績CSV・247列。週次の結果取込と同じ書き出し）。
   - これはTARGETのデータを見て書き出すだけで、TARGETには何も追加しない。
   - ただし、この日の成績がまだTARGETに取り込まれていない場合は、データ登録が必要になる。**その場合は作業せずに会長に相談する。**
2. 開発部が補完スクリプトを作る。日付・場所・レース番号・馬番でログと突き合わせ、次の欄を埋める。
   - `ai_top1_odds` … ◎の馬の確定単勝オッズ（31件）
   - `win_name` … 勝ち馬の名前（「不明」30件）
3. 元のログは `daily_results_log.backup_YYYYMMDD.json` として残し、書き換え前後の差分一覧（どのレースのどの欄を何に変えたか）を会長に見せてから、本体に反映する。
4. すでに入っている5件のオッズとCSVの値が一致するかも確かめる（一致しなければ突き合わせ方が間違っているので止める）。

- 長所: 正確で速い。31件ぜんぶ一度に埋まる。今後の週も同じ方法が使える。
- 短所: PC上でTARGETを操作する必要がある（会長のPCで動くClaudeか、会長ご自身の書き出し）。

### 案B　JRA公式サイトの結果ページから読み取る

Claude in Chrome などで、31レースのレース結果ページを1つずつ開いて◎の馬番のオッズを読み取る。

- 長所: TARGETを触らない。
- 短所: 31ページ分の手作業で、読み取りミスの心配がある。
- 社長の考え: 単独では使わず、**案Aの結果から5レースほど抜き取って照合する確認用**に使う。

### 案C（推奨）今後の記録漏れを防ぐ

成績を記録しているスクリプト（`log_daily_results.py`、PC側にあってこのリポジトリには無い）を、◎が外れたレースでも◎の単勝オッズを書くように直す。

- 原因の見込み: 「勝ち馬のオッズ」を◎のオッズとして入れているため、◎が勝ったときしか埋まらない。スクリプトを見て確かめる必要がある。
- 進め方: スクリプトをこのリポジトリに入れていただくか、PC上で開発部が読み、直し方を差分にして改めて会長に見せる（直すのはその承認後）。

## 4. 検証部の判定

- 判定: 対象外（指数の変更ではなくデータ整備）
- 補完後に検証部が行うこと: 抜き取り照合（案B）と、補完前後で的中率が変わっていないことの確認（変わるのは回収率だけのはず）。

## 5. リスクと戻し方

- 突き合わせのずれで別の馬のオッズが入るおそれ → 既存5件との一致確認と抜き取り照合で防ぐ。
- 戻し方: バックアップしたログに戻すだけ。
- 補完しても36レースなので、回収率はまだ「参考値」。販売判定には使わない。
